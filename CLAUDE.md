# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

HTML game prototype: a lab rat escapes a dark cardboard maze with a flashlight strapped to its back. All the code lives in `index.html` (inline CSS and JS, no dependencies, no build step); the only assets are the music in `audio/`, the logo in `img/logo.png` (840 px web version; the original is in `concept/logo.png`) and two screen backgrounds, `img/fondo-maquina.jpg` and `img/fondo-bioterio.jpg` (JPG versions of the PNGs the user left in `concept/`, "bg_maquina_01" and "bg_bioterio_01", the latest versions; same geometry as the ones before), plus `img/salto-ratita.png` (the prize rat's jump, traced from the user's GIF, see `reveal`), `img/fondo-cinetica.jpg` (1280 px JPG of the user's `concept/bg_cinetica_01.jpg`, the golden speed lines behind the prize rat) and `img/fondo-ratalab.jpg` (the user's `concept/bg_ratalab_01.jpg`, a lab counter behind the front-facing prize rat). The game is called **Maze Mouse**. The only external resources are the Google Fonts fonts (Permanent Marker, Special Elite), with fallbacks. `concept/` holds the reference concept art (top-down view, cardboard walls with a corrugated edge, white rat with a harness) and the game doesn't load it.

The UI, the code comments and the README are in Spanish (Rioplatense, with voseo: "presioná", "escapaste"). Keep that tone.

## Run and test

There are no commands for building, linting or running tests. You open `index.html` in a browser, and with the built-in browser pane that's `preview_start` with `url: file:///C:/Claude/Laberinto/index.html`.

Quirks of the browser pane that affect testing:
- The page loads as a `data:` snapshot, so after each edit you have to navigate to the URL again. In that snapshot images and audio do not load; to see the backgrounds, serve the folder over http (a tiny Node static server on a port, started with `preview_start` from `.claude/launch.json`) and open `http://localhost:<port>/`.
- `requestAnimationFrame` is heavily throttled there, so simulated keypresses barely move the rat. To test logic, call the global functions directly from `javascript_tool`. Top-level `const` and `function` declarations are reachable from there. For example, `keys['arrowup']=true; for(...) update(1/60); render();`.
- `loadLevel(n)`, `startPlay()`, `resetRun()` and `castRays(x,y)` let you set up any situation. Setting `G.light=1` and calling `render()` gives you a lit frame for a screenshot.
- In the pane the `data:` URL has no `localStorage` (the game tolerates it with try/catch); to test progress, look at `Story.data`.
- Mobile mode can't really be tested in the pane, because with the local file touch emulation doesn't trigger on reload. Add the `touch` class to the `body` and simulate the finger with `PointerEvent` (`pointerdown`/`pointermove`/`pointerup`, using the same `pointerId`) on `#stickZone`. Final testing is on a real phone, at the Pages URL.
- The canvas can be 0×0 when the page loads, so `resize()` keeps it at least 1 px. In `frame()`, `requestAnimationFrame` is scheduled before `update`/`render` so that an exception doesn't kill the loop.

## Script architecture (`index.html`)

**Tunable constants** at the top: `C` (cell size, 64 world units), `T` (wall thickness), `K` (apparent wall height), speeds, `LIGHT_R`/`CONE` (flashlight), `RAYS`. Progression comes from `SIZES`/`sizeFor(n)` (maze columns×rows), `viewCells(n)` (how many cells across fit on screen, i.e. the zoom, which gets closer with each level) and `timeFor(n, pathCells)` (time limit from the shortest path length).

**Modes** (`G.mode`):
- **Challenge** (`loadLevel(n)`): infinite random levels. The seed is `G.baseSeed + n*7919`, and the base seed changes with every new game.
- **Story** (`loadStory(i)`): fixed levels from the `LEVELS` table (`seed`, `size`, `loops`, `traps`/`sticky`/`cheese`/`doors`, `intro`, optional `time`). It uses the zoom and time factor of challenge level 5 (`STORY_VIEW`) plus extra time for cheese and glue.
- **40 levels:** each mechanic is introduced on its own and then combined. Level 1 has no cheese (you only learn to escape in time), level 2 has one, and levels 3–6 ask for 2, 3, 4 and 5 (placing one spare); 7–12 are glue, 13–20 traps (with glue), 21–28 doors (with everything before), and 29–40 everything together. From level 2 on every level has cheese (the ones that had none got one), so the cheese star is always a goal. Mazes grow from 10×6 to 24×14, with more items as they go. Time is computed automatically; the level selector scrolls (5 per row, 4 on mobile). All levels were checked to place every item they ask for. The `intro` phrase of each level is no longer shown.
- **Light and dark levels** (Story only, the user's design): most levels have the maze light on (`G.dark` false): the whole maze is visible with an even ambient (`roomLit` in `render`, `ROOM_AMBIENT`), the rat has no harness and no flashlight on its back (`bare` in `drawMouse`; no beam, no lens glow, `G.light` held at 1), the clock runs freely and there is no losing by time (`G.timeLeft` does not drain, no siren, no ticks). 30% are dark (`DARK_LEVELS`: 4, 8, 11, 15, 18, 23, 26, 29, 32, 35, 38, 40; the first level and the one that introduces each mechanic, 2, 7, 13 and 21, are lit so it is learned seeing it): the flashlight has a battery of `LAMP_MAX` 60 s (`G.lamp`, `G.timeLimit` = 60, `G.timeLeft` drains, and when it runs out you lose as before), shown in a new HUD sticker under the cheese, the same size as the cheese one (`#lamp`: an invisible text line gives it the cheese's height, and the cells are sized in em; a battery with 4 blocks of `LAMP_BLOCK` 15 s; the block being used counts as lit; with one block left it turns orange, and in the last 10 s red and blinking; it takes the cheese's place when the level has none, `.up`). Batteries in the maze (`battery` items, `placeBatteries`, `drawBattery`: a lime AA cell with a bolt that pulses slightly) fill the whole battery (back to 60 s, `Snd.battery`); there is one for about every `BAT_EVERY` 45 s of the time the level used to give (`max(1, ceil(old limit / 45) − 1)`: 1 to 6), spread evenly along the shortest path (the nearest free path cell if a spot is taken), so following the path the stretches between them stay well under 60 s. Dark levels also get a very faint even ambient (`DARK_AMBIENT`, times `G.light`, so it goes out with the flashlight), so the maze is a little less black. The time used is `G.elapsed` (it used to be `timeLimit − timeLeft`), which feeds the HUD clock, the stars and records. The star times still come from the old time limit. Losing by battery shows "¡Sin pila!". Challenge is still dark with its old computed time and no batteries (to be reviewed).
- **Progress:** (`UNLOCK_ALL` is true for now, for testing: every level shows unlocked; set it to false to go back to unlocking one by one.) `Story` saves it in `localStorage` (`raton.story = {unlocked, stars[], best[]}`; `best` is the best time per level). Stars (`starsFor(time)`), in Story each goal adds one on its own (the user's rule): ★ for escaping, +1 for collecting the level's cheese goal (`G.cheeseTotal`; level 1 has none, so it comes free) and +1 for escaping in the target time (`G.star3`) or less; so with the time but not the cheese you get 2. Challenge still uses the old rule until the user reviews it: ★★ for taking less than `G.star2` and ★★★ for less than `G.star3` with all the cheese. Both times are computed per level by `starTimes(extra)` (called from `loadStory` and `loadLevel`) from the ideal route (shortest path at full speed, `pathLen · C / SPEED`) times 1.8 and 1.3, plus the same cheese and glue extra as the time limit and a fixed +3 / +2 s (turns cost time, especially in small mazes), rounded. The intro card (`showIntro`, same layout in both modes) uses the results card's format (`.win`, see below): the paper title tag with "Nivel N" big and the level name underlined under it (in Challenge "Desafío N" / "Laberinto W × H"), a paper box "Objetivo" with tape corners (`.wgoal`, `.whead`) holding the cheese to collect and the target time (`G.star3`, `fmtMS`) side by side with a divider (`.wgrid`, `.wg`; each an icon on the left and the number with its label under it, "Quesos" / "Tiempo"; without cheese only the time, centered) and a wide green "Jugar" button (`.wplay`, `start`), after the user's reference. The time limit, the ★★ time and the chips of what is inside are no longer shown there. The HUD clock counts UP in both modes (time used, `fmtUp`), the same unit as the results and goals; the limit shows in the flashlight battery and the siren. Stars give no coins (that was removed: it was hard to communicate).
- **Results screen** (`showWinCard`, both modes; in Challenge, whose mazes are random, the record and stars count while you repeat that same maze, `G.chBest`/`G.chStars`), after the user's mockups, with its composition and colors in the game's cardboard style (`#card:has(.win)`: light cardboard, rounded, dark edge; everything inside `.win`): a paper title tag that sticks out over the top edge (`.wtitle`: "Nivel N" big, "¡Completado!" underlined; "Desafío N" in Challenge), the stars in a dark cardboard panel with a paper frame, tape corners (`.tp`) and yellow ray marks (`.wstars`, `.wray`; faceted SVG stars from `starSvg` that drop in one by one, the missing ones a shadow), two equal paper boxes (`.wrow`, `.wstat`: icon on the left, label and number beside it) for the cheese (only in cheese levels; otherwise the time box takes the full width) and the time (`fmtMS`, "00:32", stopwatch `WATCH_SVG`), with a red "¡Nuevo récord!" stamp at the bottom of the time box when you beat your record (times floored, records compared in whole seconds), a "Recompensa" box with two coins and `+G.runCoins` (`.wreward`), the yellow machine button (`machButton`, `#machSlot`, refreshed by `refreshPrize`: a prize capsule drawn once by `capsuleImg`, "¡Activá la máquina!" and the price in a pill; without enough coins it is muted and says how many are missing, and still opens the machine) and "Repetir" (paper, `RETRY_SVG`) / "Siguiente" (green, `PLAY_SVG`). While a won or lost card shows, the level and clock stickers of the HUD are hidden (`updateButtons`; the card already shows both and its title covered the clock on phones). On short screens `fitWin` shrinks the whole `.win` with CSS `zoom` so the card fits without covering the top buttons (it runs in `showCard` and on resize). The lose cards (`lost()`, trap or time) use the same format: the title tag with "Nivel N" and, in red (`.wtitle.lose`), "¡Atrapado!" or "¡Se acabó el tiempo!", a paper box with a drawing and what happened (`.wlose`: a closed trap, `TRAP_SVG`, or a switched-off flashlight, `DEAD_LAMP_SVG`, "La trampa se cerró." / "La linterna se apagó." and "Volvés a la entrada del mismo laberinto."), the machine button and a wide green "Reintentar" (`retry`). The old prize notice (`prizeBlock`, the bar) is gone. "Niveles" is a back arrow at the top left of the screen (`#btnBack`, on the results, on the level select, and on the Ratitas and Máquina screens, which have no "Volver" button anymore (on the machine only while it is at rest or showing the prize); from the select and Challenge it goes to the title; on the Bioterio and the Máquina it shows a house instead of the arrow (`updateButtons` swaps the icon) and goes to the title; the coin counter moves under it, `#coins.below`).
- **Shared building:** both modes go through `buildMaze(W, H, seed, loopFrac)`.

**Menus**: `title` (logo, controls and the Story/Challenge/Ratitas/Máquina buttons, with no intro text or mode descriptions; keys 1/2) → `select` (level grid for Story titled "NIVELES", with no description, no scrollbar, no bottom button and no SPACE hint: the top-left arrow goes back and SPACE still plays the last unlocked level) → `intro` … The card buttons use `data-act` and are resolved in `act()`. The global click handler checks them before `primaryAction()`, and in `title`/`select` a click outside a button does nothing. Pause and options live in one panel (`#opts`, `openOpts`/`renderOpts`/`closeOpts`), opened by the gear button at the top right (`#btnGear`, the only button there) or P/Esc: while playing it pauses and shows "PAUSA", Música and Sonido switches, the house (back to the title, also Q) and "Reanudar"; on any other screen the gear opens the same panel as "OPCIONES" with "Cerrar", on top of whatever card is showing. Toggling Música/Sonido only slides the switch (`renderOpts` updates the open panel in place instead of rebuilding it). Closing it (resume, Cerrar) is animated too: it shrinks away like it came in, reversed, and the dark backdrop fades (`closeOpts` adds `.closing`, `optsOut`, then hides it). Every change of screen goes through a quick fade to black and back (`fadeTo(fn)`, `#fade`, `FADE_MS`): the acts in `FADE_ACTS` (title → select, level → intro, next, levels, Bioterio, Máquina, home, back), SPACE on the select screen and the back arrow; `act` calls `firstGesture()` before fading so the music still starts within the tap, and `actNow` does the actual change. A provisional test button, "Luz", sits at the bottom right of the title screen only (square, with the bulb icon above the text; `#btnLight`, `debugLight`, saved in `raton.debugLight`). When on, the game adds an even ambient light (`DEBUG_AMBIENT`) to `lightCv`, so the whole maze is visible; the flashlight and everything else work as usual. On mobile and touch screens the scrollbars are hidden, though you can still scroll. The title and select screens use `titleBackground()`: a fixed maze sized to the screen (4 cells larger, rebuilt if the size changes, `G.titleSize`) with the camera fixed at its center, so its edges never show on PC or mobile, and no rat (`render` skips it when `menu`), softly visible thanks to an even ambient light (`MENU_AMBIENT`, only in menus; the game keeps total darkness). Every 2–5.5 s an old bulb flickers somewhere on screen for a moment (`menuFlicker`, `MenuFl`), a round light (`drawBulb` instead of the flashlight cone) cut by the walls.

**Maze** (`genMaze`): recursive backtracker on a W×H grid. Walls are stored as `hW[r][c]` (top wall of row r) and `vW[c][r]` (left wall of column c). The entrance is always on the right side (`entRow`) and the exit on the left (`exitRow`). `loopFrac` opens walls to create cycles. `bfs(m, c, r)` returns maze distances, used by `pathLen` and to place items. "Retry the same level" relies on not regenerating: `resetRun()` only repositions the rat, resets the timer and restores the items.

**Items** (`G.items`, generated in `placeItems` from the level rng, so they're fixed):
- **`trap`**: only in dead-end cells off the shortest path and away from the entrance and exit, facing the opening. Touching it closes it and calls `startDie('trap')`, which shows "¡ATRAPADO!". It's a procedural placeholder until the user sends an image.
- **`sticky`**: a tray that slows you down, and the more paws on it the stronger the brake (`STICKY_ON` minus `STICKY_PAW` per paw; with all 4 at 14%). After leaving it you recover from `STICKY_SLOW` over `STICKY_T` s (`stickyFactor`). It only goes on straight corridor stretches (two cells in a row with walls on both sides, never at junctions or corners), centered and almost as wide as the corridor. More likely near the exit.
- **`cheese`**: preferably off the path. A level can place more than it asks for (`cheeseGoal`), so there are a few to spare. `G.cheeseTotal` is the goal, the HUD (`#cheese`) shows collected/goal, and reaching it counts toward the stars.
- **`door`**: a one-way door in a wall between neighboring cells that are 8 or more cells apart through the maze, at least 3 cells from other doors and never in a cell another item uses (they replaced the cardboard-roll tunnels). Side A has the hole and side B has a thin cardboard curtain, larger than the hole, hung by tape above it. A is the cell farther from the exit, so it's a shortcut toward the exit. `doorSolids` cuts the wall at the hole in `G.solids` and adds the hole as its own rect (`d.rect`, with `door`); `G.rects` stays whole, so walls are drawn and block light as before (with a curtain lifted, `castRays` uses `G.holeRects`, which have the hole). `doorCheck` (at the start of `collide`): if the rat touches the hole with its center on side A, `d.passing` and the hole stops colliding until the rat leaves it. From side B it's a wall and the curtain rattles (`d.rattle`). Approaching from A slightly off-center, a funnel nudges the rat toward the middle. The tail ignores the holes. `updateDoors`: the curtain angle (`d.ang`, spring) rises with how far the rat sticks out on side B, falls when it leaves, hits the frame (`Snd.flapShut`) and rests at `DOOR_REST` so its edge shows from above.
- **Look:** the drawings follow photos the user sent, seen from above:
  - Trap (`drawTrap`): wooden board, wire bail, spring, metal trigger plate and a cheese cube.
  - Glue (`drawSticky`): black plastic tray with bluish-gray glue, corner screws and a center button. It's rectangular (`TRAY_L`×`TRAY_W`) and laid along the corridor; it counts as stepped on if it touches the rat's body.
  - Cheese (`drawCheese`): a wedge with a curved rind and 3D effect. Its top face is projected like the wall tops, with height `CHEESE_H`, and you see the sides facing the camera. Its size is `CHEESE_SCALE`.
- **Gallery:** `index.html?galeria` shows all the items large and lit, plus the rat for scale, to review designs with the user. In the browser pane the query string is lost, so call `window.render = renderGallery` instead.
- **Drawing:** traps, glue and cheese are drawn in `drawFloor`, so they're only visible with light. Doors (`drawDoors`) are drawn in `drawWalls` in three passes, projected with the wall parallax: the curtain behind the wall when the camera is on side A ('back'), the dark hole on the side face of A ('hole'), and the curtain plus hinge tapes in front when the camera is on side B ('front'). Since they're in `wallCv`, a lifted curtain covers the rat as it passes underneath. A dark shadow on the floor on side A (`drawDoorShadow`) marks the hole from above, along with a strip of caution tape like the start one but darker (`drawStartTape` with `shade`).

**Coins and rats** (phase 2, based on Crossy Road; placeholder art):
- **Coins** (`coin` items, `placeCoins`): few, and placed so they create decisions, not chores (the user's design; the economy aims at about one machine spin, `COIN_PRICE` 20, every two or three Story levels): in Story 2–3 single coins spread along the shortest path and one off-path treasure of 3–5 coins (two treasures in mazes of 220+ cells), sized by the detour (about one coin per `COIN_DETOUR_S` seconds), preferring dead ends; that is about 6–9 per level, ~300 for the whole Story. In Challenge level N has exactly N coins (`budget`: up to 2 singles on the path, the rest in treasures of up to 5), so it works for farming and pays to go deeper. Treasures go in a row along a straight corridor (two rows if more than 4) or in a ring. `G.coinsTotal` counts them for the results screen. They use their own rng (`seed + 777`) so they don't move the other items. Picked up by passing near them (generous radius, `PICK_COIN`, made bigger at the user's request, like the cheese's `PICK_CHEESE`; `Snd.coin`). They're kept even if you lose (`Wallet`, `raton.coins` in `localStorage`), and collected coins stay collected when retrying the same level. `drawCoin`: silver coin after a design the user sent (one light gray face, `COIN_FACE`, with two full-width grooves, each a dark line, a mid-gray body and a light line below: `COIN_BANDS`, no outline) that spins on itself like a flat cylinder (slower as it passes edge-on, without stopping, and faster showing a face: the angle is warped with a double sine), and at the same time it slowly rotates around its center (`COIN_ROLL`), so the flip axis keeps turning: the face narrows with the cosine of the turn and the edge band (`COIN_T` thick) widens with the sine, so edge-on only the side rectangle shows, with the grooves continuing across it; the back face is a darker version of the front (`coinBack`) with three thinner, evenly spaced grooves instead of two (`COIN_BANDS_BACK`, after another reference of the user; the edge continues the grooves of the face that shows), so you can tell which side is showing as it turns; picking one up throws small white diamond sparks (`G.fx` with `sq`, spinning and shrinking); `COIN_ICON` builds the same design as an inline SVG for the HUD and buttons, with a gray outline as wide as the HUD cheese icon's. The item gallery (`?galeria`) shows it spinning and facing front. The counter `#coins` is visible at the top left corner (except on the level select and behind the end-of-level cards, won or lost: coins are not used there and it covered the card on phones; it shows again on the Bioterio / Máquina), a bit bigger (under the back arrow on the screens that have one); the cheese counter goes under it in the game (hidden behind the won/lost cards too, which show the cheese themselves), and the win card shows `+N` (`G.runCoins`).
- **Rats** (`RATS`, 21 entries: name, fur, ears, harness, flashlight body, eyes, paws/tail, plus spots for Pandita): One palette per rat for all three views (maze, side, front): `portraitOf(i)` (fur, outer ear `ear`, inner ear `earDark`, ear line, nose, paws, tail, face and leg lines; defaults derived from `RATS` fur and ears, overridable in `PORTRAIT_COLORS`) is the source, and `skinOf(i)` takes fur, ears, inner ear, nose, paws and tail from it for the maze rat, adding eyes, harness, flashlight and spots from `RATS` (the paws/tail column of `RATS` is no longer used), plus shades mixed with black/white; `drawMouse` takes every color from `curSkin()`. The flashlight head and lens are the same for all. Owned and selected rats are saved in `Skins` (`raton.skins = {owned, sel}`); Albina (0) is the starter.
- **Portrait** (`drawRatPortrait`): outside the maze the rats are shown in a separate flat side view (facing left, no harness or flashlight), redrawn after a later reference the user sent: a teardrop body with the back high toward the rump and a wedge head, a flat belly on the floor, a round back ear (inner-ear color) and a big round front ear with a darker inside and a fold line over the top, a round eye with a shine, a small nose at the tip, three whiskers fanning back, two dome-shaped paws with two toe marks each, a "C" line for the thigh and a ")" for the shoulder, and a tail that leaves the rump to the right, loops down and runs back left under the body to a thin tip. It is drawn in the reference image's own coordinates (1536 × 1024, floor at y = 765), mapped by `R` into the old portrait frame, so cages, galleries and the library did not need changes. Colors come from `portraitOf(i)`: Albina's are hand-picked in `PORTRAIT_COLORS`, and the rest are derived from `RATS` with the same proportions (tail, nose and paws take the light ear color). A rat can be tuned by hand in `PORTRAIT_COLORS`, overriding only some colors (`ear` is the front ear and feeds nose, paws and tail; `earDark` is the back ear and the inside of the ear; `line` is the face lines, whiskers and mouth; `legLine` the leg lines, thigh, shoulder and arms, defaulting to `line`); Pinky (7), Wasabi (18) and Radium (19) have their ears set that way,. `t` animates it: breathing, blink, ear twitch, tail sway.
- **Front view** (`drawRatFrontPose(c, cx, cy, size, i, t, land, curl)`, with the wrappers `drawRatFront` for sitting and `drawRatFrontBall` for curled up): a front-facing rat with two poses built from THE SAME pieces, so one can turn into the other without swapping drawings (the user asked for it): `curl` 0 is sitting and 1 is curled into a ball (round ball body, ears hidden inside the ball behind the head (when it uncurls they come out from there and unfold, on their own faster timing, already out halfway, `eu`), eyes closed, hands covering the mouth, feet tucked under, tail hugging the ball), and in between every piece moves, turns and resizes (the belly outline is sampled into `FRONT_N` points, the bell and the circle point by point; the tail is sampled the same way). Sitting it is after a reference the user sent (big round head merged with a body that drops straight from the head and opens into two round hips reaching the floor (reshaped, like the feet and ears, to match the last frame of the user's jump GIF, so the crossfade at the end of the jump shows no double feet; before it was a bell with a flat base), big round ears with a darker inside and a line, red eyes with a highlight, small triangular nose and an "ω" mouth, three straight whiskers per side in a fan, arms drawn as a line down to the paws held together in front (the user tried them further apart, like the GIF, and asked for them back), whole oval feet whose center sits on the line where the body ends (lowered at the user's request, so they are a bit lower than in the GIF), the tail curling up on the right a little higher than it used to and the tail curling up on the right). Colors come from `portraitOf`/`skinOf`, so it works for any rat; `t` animates breathing, blink, an ear twitch, the tail and the whiskers. Sitting, the tail moves like a cat's in a seamless loop: a wave travels from the base to the tip (each piece of the chain turns from its rest shape, more toward the tip and with a delay, plus a second harmonic for the tip flick; `TAIL_W` speed, `TAIL_SWISH` amount), while the part lying on the floor stays still. Breathing stretches only the belly: the head, ears and face are not deformed, they just rise and fall with it (`lift`). Every so often the head tilts a little to one side or the other, or back to the middle, at random but deterministic from `t` (`headTilt`: segments of `HEAD_SEG` s, each with its own target, start time and duration, eased; pivot at the neck, `HEAD_PIVOT`), and after the machine landing it stays still for `HEAD_WAIT` (6 s, well after the bounce; the user asked twice for a longer wait) and then eases in over `HEAD_EASE`. A neck fill on each side (a curve that leaves the widest point of the head along its edge, wherever the tilt puts it, and enters the side of the body vertically; it used to be almost straight and looked like a cut at the shoulder when the head tilted; the hidden top of the body is also rounded so its corners never show) removes the pinch between head and body, so the outline stays smooth when the head tilts; curled up it shrinks into the ball. Every so often it sniffs: the nose trembles quickly for half a second to almost one (rising a little and squashing), easing in and out, and the whiskers follow it; the whiskers also sway gently all the time (`sniffAt`, `SNIFF_SEG`, `SNIFF_HZ`, random but deterministic from `t`, never during the landing). Every so often one hand gives a quick shake that dies out, pivoting at the wrist where the arm ends (`handShake`, segments of `HAND_SEG` s per hand, `HAND_SHAKE_T` long), never during the landing. `land` (seconds since it touched the floor) plays a landing bounce, a chain of damped rebounds each a bit later than the previous one: the body squashes and widens with the pivot at its base (the back feet stay put), the hands follow slightly later, then the head drops, rises a bit past its place and settles, then the nose, then the whiskers (tips more than the base); the ears open outward, the tail bounces and the eyes close for an instant on impact. **Rendering pipeline** (`render`). This is the core of the visual look and needs care when you touch it:
1. Fully lit scene: floor (`drawFloor`, using a tiled texture pattern) on the main canvas, and walls (`drawWalls`) on `wallCv`. For the 3D effect, each wall's top face is the base rectangle scaled by `(1+K)` around the camera, and only the side faces facing the camera are drawn.
2. Light map: `castRays` fires `RAYS` rays from the flashlight against the wall edges (all axis-aligned) and gets a visibility polygon. On `aCv` the beam sprite (`coneCv`, generated pixel by pixel at startup) is drawn, clipped with `destination-in` to that polygon. That's the floor light. `drawCone` also adds a dim round glow around the flashlight (`AURA_R`, `AURA_A`), so the maze is a little less dark near the rat, behind it and to the sides too; it is clipped by the same visibility polygon, so walls cut it, and the beam itself is unchanged (the user asked for it). On `bCv` the same beam is clipped to a polygon extended by `T+6` (plus its version projected by `(1+K)`) and to the shape of `wallCv`, so the top faces and sides of the walls get lit. Both are added (`lighter`) into `lightCv` over black.
3. `multiply` of `lightCv` over the scene: anything without light stays fully black. "Total darkness" is a design decision: lit areas are not remembered. Before it's added to `lightCv`, the floor light goes through `blurCv` (half resolution, `ctx.filter = blur`) so the shadows have a soft edge (`SHADOW_SOFT`). If the browser doesn't actually blur with `filter` (Safari/iPhone: `CAN_BLUR` is detected by testing a real blur), the shadows stay hard. An alternative blur that shrinks and re-enlarges the image was tried, but on iPhone the shadows flickered a lot, so it was removed.
4. The rat (`drawMouse`, procedural) and the lens glow are drawn after the darkness, so they're always visible. The rat is drawn opaque in its own canvas (`mouseCv`, only in a rectangle around it) and darkened with `source-atop` based on the light. Don't use `globalAlpha` to dim it: it becomes see-through and its overlapping parts show through.
5. The walls are taller than the rat, so they get drawn again on top of it, already lit (`wallCv × lightCv`, built in `litCv`), but only in a rectangle around the rat.
6. Iris wipe: a black circle centered on the rat. Before it, `exitDarkness()` darkens the light and the rat while it crosses the exit threshold (exit row only). It closes when you go through the exit, and the win card appears once it's closed (`showWinCard`). It opens in `startPlay`. Its state is `G.iris` (1 = open) / `G.irisTarget`, and it takes `IRIS_T` seconds.

The wall light (`bCv`) is also blurred (`WALL_SOFT`) before being clipped to the shape of the walls, so the edge of the lit area on the wall tops doesn't look like a hard circle. Camera shake (`G.shake`) builds up when you bump several times in a row (less than 1.2 s apart). It only offsets the camera while drawing (`render` adds it to `cam` and takes it back off at the end).

The eyes sit close to the snout, red with a white highlight (only Albina has a red glow around them, `eyeGlow` in `skinOf`); closed, they're a short sideways line curving toward the back. The whiskers start next to the nose and fan out to the sides. The paws sit slightly under the body, with fingers pointing forward and outward: the front ones are beside the eyes, in front of the ears, and the back ones are at the hips. The flashlight on its back (inspired by a hand flashlight the user sent: bluish-gray body, yellowish COB panel) has a battery bar that shows `timeLeft / timeLimit`. It drains toward the tail, turns orange below 25% and red below 10%, and blinks in the last 10 s. The head and lens of the flashlight (x 4..8.6) shouldn't be changed: the user likes them as they are. When it bumps into a wall, `hx()` compresses everything in front of the shoulders (the head pulls back) and `updateTail` adds a quick tail wag. The head turns on the neck (`NECK`, `M.headA`): the silhouette bends gradually (helper `P`) and the face (nose, ears, eyes, whiskers) rotates as a whole. It leads into the turn, and when idle `animMouse` sometimes makes it look to one side, or to one side and then the other, before returning. The paws step for real (`updateFeet`, `M.feet`, world coordinates):
- **Stepping:** the gait is tied to distance, not time. A cycle (`M.gait`) advances by how far the paws' rest spots (`FEET`) move, whether walking or spinning in place, at one cycle every `STRIDE` units. Each diagonal pair runs half a cycle from the other, so they're always in sync: slow means slow steps and fast means fast steps.
- **Phases:** a paw spends `SWING` of the cycle in the air, going from a bit behind its rest spot to a bit ahead. The rest of the time it's planted, still on the floor. Front and back paws have the same reach; to keep the hands close to the arms, their rest spot was moved back instead (a shorter reach makes them drift back while planted).
- **Stopping:** if it stops with a paw in the air, that paw finishes its step on its own.
- **Slip:** a planted paw follows the body by `FOOT_SLIP` (a slight drag). That allows a long `STRIDE`, so the steps aren't too fast at full speed, without the paws drifting away from the body.
- **In the air:** it shrinks, gets lighter and turns outward. The step sound plays when it lands.
- **Limbs** (`limb`): fur ovals that follow each paw (stretching and rotating), cover the gap between paw and body, and are drawn under the body. Thighs go from the hip to each back paw; thinner arms go from the shoulder to each front paw.
- **Glue:** the steps are slower and "tugging", and after leaving the glue it leaves sticky footprints (`G.prints`, `PRINT_LIFE`, `drawPrints`; made darker at the user's request so they show).

The torso sways and bounces to the rhythm of the steps. When the rat spins in place (`M.spin`: turning fast without moving forward), the head turns more and the torso compacts: shorter and a little wider. When it pulls free of the glue (`M.stretchT`, `STRETCH_T`, `stretchAmount`), the torso stretches and thins for a moment, with a small rebound (inertia). The flashlight is rigid: it undoes the torso scale (`tsx`/`tsy`) around its center (`FCX`), so it follows the back without deforming. When it gets caught in a trap (`M.caught`), both ears shake and the tail goes straight and wags side to side fast for `CAUGHT_T` (1 s, fading via `caughtAmp`), then it stays completely still with its eyes closed. From the moment it's caught it takes a squashed pose (`M.squash`): paws splayed (front ones forward and out, back ones stretched backward and out), torso flatter and wider, ears drooping to each side; `animMouse` makes no more gestures, the whiskers stop, and `updateTail`/`updateFeet` freeze; it also plays a rat squeal (`Snd.squeal`). The flashlight dips slightly every 5–11 s (`DIM_T`, `DIM_DEPTH`), smooth, not a flicker; after bumping several times in a row it falters (`G.faltT`, `FALTER_T`): a couple of quick dips that fade on their own. Footsteps vary in volume, pitch and duration each time, and they're muffled (lowpass-filtered noise plus a soft low thump, no highs). On a wall bump there's a 70% chance of a squeal (`Snd.squeak`) that varies in pitch, length, number of chirps and direction.

The tail is also in world coordinates: it's a chain of `TAIL_N` points (`M.tail`, computed in `updateTail`). Each point moves toward a rest shape (a ripple tied to `M.phase`, a sway tied to `G.time`, and a curl tied to `M.turnV`), keeps the segment length fixed and is pushed out of the wall rectangles, so it never goes through walls. It's looser toward the tip, so it lags behind during turns (inertia). Safeguards so it never goes through a wall, which happened on iPhone: the body has a third collision circle at the hip; the tail root moves toward the rat if there's a wall on the body axis; each point moves at most `MAX_STEP` per frame (less than the cardboard thickness); and when rebuilt (`resetRun` sets it to `null`) it starts bunched at the base and grows backward (before, it was built straight and went through the start pen wall). `animMouse()` drives the gestures: the bump against a wall (`M.bumpT`: ears flap, whiskers tremble, eyes close), the random blink (`blinkT`), and the left or right ear twitch (`twitch`), which only happens after a second without input.

**States** (`G.state`): `title` → (`select`) → `intro` → `play` ⇄ `paused` → `won` | `dying` → `lost` (`G.dieReason`: `time` or `trap`). The cards are HTML (`#card`), and the HUD is DOM over the canvas, the same on PC and mobile (after a layout the user sent): the coin counter at the top left with the cheese counter under it, the level label small and centered above the timer, and the gear at the top right. There is no house button in the HUD anymore (it is inside the pause panel). The canvas is `position: fixed; inset: 0` and its size comes from `clientWidth`/`clientHeight`. Don't go back to `100vh`: on phones it includes the browser bar and pushes the camera off center. After following the rat, the camera keeps it inside `safeZone()`: 15%–85% of the screen, and on mobile between 80 px below the HUD and 66% of the height (so it doesn't end up under the HUD or under the thumb using the joystick). When time runs out, the light flickers and goes out (`dying`) and you go back to the start of the same maze. The camera (`camTarget`) follows the rat with some lookahead and is clamped to the maze edges when the maze is larger than the screen.

**Input**: directional control on both platforms, with no tank controls (the user tried them and changed their mind, and the gyroscope was dropped too because it was uncomfortable). Each frame, `update()` computes a target direction on screen. It comes from the floating joystick on mobile (`Stick`, with `#stickZone` covering the screen and the base `#stick` appearing where you put your finger) or from the arrows/WASD on PC (↑ = up, and they combine into diagonals). The rat turns toward that direction gradually, limited by `TURN`, and moves at `SPEED × magnitude × cos(angle difference)`, so it first turns and then moves forward. Space, click or tap trigger `primaryAction()`. Mute is saved in `localStorage` (`raton.muted`).

**Sound** (`Snd`): the effects are all synthesized with WebAudio (oscillators and filtered noise, no files), including the "whoosh" of cards entering (`cardIn`) and leaving (`cardOut`). `Snd.init()` runs on the first keypress because of the browsers' autoplay policy. The music is the only file: `audio/laberinto-de-circuitos.mp3`, in `Music` (an `Audio` element on loop, separate from WebAudio). It starts on the first tap or keypress (already on the title screen; browsers don't allow audio before a gesture), fades in to a low volume (`Music.vol`, so it doesn't drown out the effects), and pauses and resumes with the pause. Music and effects have separate switches in the gear panel and separate mute states (`raton.musicMuted` / `raton.muted` in `localStorage`; keys M / F). In the browser pane the mp3 doesn't load, because the local file opens as a `data:` snapshot. Test it at the Pages URL.

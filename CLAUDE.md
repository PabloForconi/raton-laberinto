## Project

HTML game prototype: a lab rat escapes a dark cardboard maze with a flashlight strapped to its back. All the code lives in `index.html` (inline CSS and JS, no dependencies, no build step); the only assets are the music in `audio/`, the logo in `img/logo.png` (840 px web version; the original is in `concept/logo.png`) and two screen backgrounds, `img/fondo-maquina.jpg` and `img/fondo-bioterio.jpg` (JPG versions of the PNGs the user left in `concept/`, "bg_maquina_01" and "bg_bioterio_01", the latest versions; same geometry as the ones before), plus `img/btn-maquina.png` (the rat in a capsule on the machine button of the end-of-level cards) and `img/salto-ratita.png` (the prize rat's jump, traced from the user's GIF, see `reveal`), `img/fondo-cinetica.jpg` (the golden speed lines behind the prize rat: since October 2026 a copy of the user's `concept/fondo-cinetica3.jpg`, 1920 px (their `fondo-cinetica2` was tried first and rejected); loaded with `?v=3` so phones do not keep the old one cached) and `img/fondo-ratalab.jpg` (the user's `concept/bg_ratalab_01.jpg`, a lab counter behind the front-facing prize rat). The game is called **Maze Mouse**. The only external resources are the Google Fonts fonts, with fallbacks: Kalam (bold, 700) is the main UI font (cards, HUD, buttons, numbers and the machine reveal texts; the user picked it from a comparison sheet, `revision/fuentes.html`, to replace Permanent Marker), Permanent Marker is only used for the pencil marks drawn inside the maze, and Bebas Neue (a narrow print font, uppercase only) is the second font: the page default and every small text that used to be in the typewriter font Special Elite (the user replaced it to use only two fonts): the "Nuevo récord" stamp, the control keycaps, the first line of the lose card ("La trampa se cerró", whose second line went to Kalam: the user swapped them), the rarity and the line under it in the machine reveal, the help hints and the color library. Sizes went up a little since it is narrow. Older notes below that say "marker font" mean this main UI font. `concept/` holds the reference concept art (top-down view, cardboard walls with a corrugated edge, white rat with a harness) and the game doesn't load it.

The UI, the code comments and the README are in Spanish (Rioplatense, with voseo: "presioná", "escapaste"). Keep that tone.

**Language:** the game can also be played in English (the user asked for it). `Lang` (top of the script) holds `'es'` or `'en'`, saved in `raton.lang`; the first time it comes from the browser language. Every visible text is written as `say('castellano', 'English')` right where it is used, so **any new visible text must go through `say`**. Level names have an `en` field in `LEVELS` (`lvName`; the 40 Spanish names were replaced by a list from the user in October 2026, e.g. Pasitos, Aroma, Quesitos, Pegote, Pringoso … Portones … Pegatrampa, Fuga, Escape, with English names written to match, all one word since the user picked them in October 2026: Steps, Cheesies, Gunk, Snaptrap, Deadends, Gate, Platter, Rattrap, Trial (levels 33 and 34 both), Timeattack, Gluetrap), rats have English names in `RAT_EN` (`ratName`: Albie, Vanilla, Flake, Ashy, Shadow, Sparky, Cocoa, Pinky, Cheddar, Nuke, Mossy, Volt, Nibbles, Blaze, Bubbles, Lilac, Merlot, Patches, Wasabi, Violet, Goldie; Nuke became Toxie when Radiactín was renamed), rarities an `en` field in `RARITY`, and the fixed HTML texts (button titles, hints) are set by `applyLangStatic`. The words painted on the maze floor at the exit and the start ("SALIDA" / "INICIO") switch too ("EXIT" / "START", in `drawFloor`); the user asked for only those, so the pencil marks stay as they are. "Bioterio" is "Vivarium" and "Máquina" "Machine". It is switched in the options panel (a third row, "Idioma" / "Language", with a globe icon and two small flags, `FLAG_AR` and `FLAG_US`: the chosen one full color with a green outline, the other faded); `relang` then rebuilds what is on screen: the panel, the card behind it (the results card through `G.winBuild`, without saving the level again), and the Bioterio / Máquina buttons and cage names. The test pages (`?galeria`, `?libreria`, etc.) stay in Spanish.

## Run and test

There are no commands for building, linting or running tests. You open `index.html` in a browser, and with the built-in browser pane that's `preview_start` with `url: file:///C:/Claude/Laberinto/index.html`.

Quirks of the browser pane that affect testing:
- The page loads as a `data:` snapshot, so after each edit you have to navigate to the URL again. In that snapshot images and audio do not load; to see the backgrounds, serve the folder over http (a tiny Node static server on a port, started with `preview_start` from `.claude/launch.json`) and open `http://localhost:<port>/`.
- `requestAnimationFrame` is heavily throttled there, so simulated keypresses barely move the rat. To test logic, call the global functions directly from `javascript_tool`. Top-level `const` and `function` declarations are reachable from there. For example, `keys['arrowup']=true; for(...) update(1/60); render();`.
- `loadLevel(n)`, `startPlay()`, `resetRun()` and `castRays(x,y)` let you set up any situation. Setting `G.light=1` and calling `render()` gives you a lit frame for a screenshot.
- In the pane the `data:` URL has no `localStorage` (the game tolerates it with try/catch); to test progress, look at `Story.data`.
- Mobile mode can't really be tested in the pane, because with the local file touch emulation doesn't trigger on reload. Add the `touch` class to the `body` and simulate the finger with `PointerEvent` (`pointerdown`/`pointermove`/`pointerup`, using the same `pointerId`) on `#stickZone`. Final testing is on a real phone, at the Pages URL.
- The canvas can be 0×0 when the page loads, so `resize()` keeps it at least 1 px. In `frame()`, `requestAnimationFrame` is scheduled before `update`/`render` so that an exception doesn't kill the loop.

## Script architecture (`index.html`)

**Tunable constants** at the top: `C` (cell size, 64 world units), `T` (wall thickness), `K` (apparent wall height), speeds, `LIGHT_R`/`CONE` (flashlight), `RAYS`. Progression comes from `SIZES`/`sizeFor(n)` (maze columns×rows), `viewCells(n)` (how many cells across fit on screen, i.e. the zoom, which gets closer with each level) and `timeFor(n, pathCells)` (time limit from the shortest path length).

**Modes** (`G.mode`):
- **Challenge** (`loadLevel(n)`): infinite random levels. The seed is `G.baseSeed + n*7919`, and the base seed changes with every new game.
- **Story** (`loadStory(i)`): fixed levels from the `LEVELS` table (`seed`, `size`, `loops`, `traps`/`sticky`/`cheese`/`doors`, `intro`, optional `time`). It uses the zoom and time factor of challenge level 5 (`STORY_VIEW`) plus extra time for cheese and glue.
- **40 levels:** the mechanics are introduced quickly, one every two levels (the user asked for a faster pace): 1 just escape, 2–3 cheese, 4–5 glue, 6–7 traps, 8–9 doors, 10–11 spinners, 12–13 gates, and 14–40 mix them all, with the maze growing evenly from 10×6 to 24×14 (`size` from the level index) and more items as they go; the introducing level of each mechanic is lit. From level 2 on every level has cheese. Time is computed automatically; the level selector scrolls (5 per row, 4 on mobile). All levels were checked to place every item they ask for. The length of the shortest path depends on the seed, not only on the size, so after a review of all 40 levels the seeds were chosen (searched in the browser) so the path (without doors) grows evenly along `22 + 178 · (i/39)^1.8` cells (±10%: 24 at level 1, 70 at 20, 123 at 30, 188 at 40; paths over ~150 cells are rare at those sizes, so 33–36 sit around 150–155), with every item placed, the doors saving between 15% and 45% of the path (so they are real shortcuts but do not halve the level), at least half the glue on the path, and all spinners and gates but one on it. A seed change remakes that maze, so its records no longer match. The `intro` phrase of each level is no longer shown.
- **Light and dark levels** (Story only, the user's design): most levels have the maze light on (`G.dark` false): the whole maze is visible with an even ambient (`roomLit` in `render`, `ROOM_AMBIENT`), the rat has no harness and no flashlight on its back (`bare` in `drawMouse`; no beam, no lens glow, `G.light` held at 1), the clock runs freely and there is no losing by time (`G.timeLeft` does not drain, no siren, no ticks). 30% are dark (`DARK_LEVELS`: 5, 9, 13, 16, 19, 22, 25, 28, 31, 34, 37, 40; **Maze** (`genMaze`): recursive backtracker on a W×H grid. Walls are stored as `hW[r][c]` (top wall of row r) and `vW[c][r]` (left wall of column c). The entrance is always on the right side (`entRow`) and the exit on the left (`exitRow`). `loopFrac` opens walls to create cycles. `bfs(m, c, r)` returns maze distances, used by `pathLen` and to place items. "Retry the same level" relies on not regenerating: `resetRun()` only repositions the rat, resets the timer and restores the items.

**Items** (`G.items`, generated in `placeItems` from the level rng, so they're fixed):
- **`trap`**: only in dead-end cells off the shortest path and away from the entrance and exit, facing the opening. Touching it closes it and calls `startDie('trap')`, which shows "¡ATRAPADO!". It's a procedural placeholder until the user sends an image.
- **`sticky`**: a tray that slows you down, and the more paws on it the stronger the brake (`STICKY_ON` minus `STICKY_PAW` per paw; with all 4 at 14%). After leaving it you recover from `STICKY_SLOW` over `STICKY_T` s (`stickyFactor`). It only goes on straight corridor stretches (two cells in a row with walls on both sides, never at junctions or corners), centered and almost as wide as the corridor. More likely near the exit, and at least half of the trays on the shortest path (off it they barely mattered).
- **`cheese`**: preferably off the path. The HUD cheese icon (the SVG in `#cheese`, which the cards copy through `cheeseSvg`, each copy with its own gradient id: sharing the HUD's `chG`, which hides behind the cards, left the cheese on the cards without its top color) is the same fat wedge as the maze cheese seen from above (`CHEESE_SHAPE` mapped into its 24×24 box: top face with the gradient and holes, the lower side and the rind side). A level can place more than it asks for (`cheeseGoal`), so there are a few to spare. Their detour (round trip from the shortest path) is capped at a quarter of the path, between 6 and 36 cells, so the cheese star costs about the same everywhere (some levels had cheese 80 cells away and others right on the path). `G.cheeseTotal` is the goal, the HUD (`#cheese`) shows collected/goal, and reaching it counts toward the stars.
- **`door`**: a one-way door in a wall between neighboring cells that are 8 or more cells apart through the maze, at least 3 cells from other doors and never in a cell another item uses (they replaced the cardboard-roll tunnels). **Rendering pipeline** (`render`). This is the core of the visual look and needs care when you touch it:
1. Fully lit scene: floor (`drawFloor`, using a tiled texture pattern) on the main canvas, and walls (`drawWalls`) on `wallCv`. For the 3D effect, each wall's top face is the base rectangle scaled by `(1+K)` around the camera, and only the side faces facing the camera are drawn.
2. Light map: `castRays` fires `RAYS` rays from the flashlight against the wall edges (all axis-aligned) and gets a visibility polygon. On `aCv` the beam sprite (`coneCv`, generated pixel by pixel at startup) is drawn, clipped with `destination-in` to that polygon. That's the floor light. `drawCone` also adds a dim round glow around the flashlight (`AURA_R`, `AURA_A`), so the maze is a little less dark near the rat, behind it and to the sides too; it is clipped by the same visibility polygon, so walls cut it, and the beam itself is unchanged (the user asked for it). On `bCv` the same beam is clipped to a polygon extended by `T+6` (plus its version projected by `(1+K)`) and to the shape of `wallCv`, so the top faces and sides of the walls get lit. The floor light has the walls cut out of it (`destination-out` with `wallCv`), so the walls get only their own light, added at `WALL_LIGHT` (0.6): a friend of the user noticed the wall tops looked brighter than the floor. Both are added (`lighter`) into `lightCv` over black.
3. `multiply` of `lightCv` over the scene: anything without light stays fully black. "Total darkness" is a design decision: lit areas are not remembered. Before it's added to `lightCv`, the floor light goes through `blurCv` (half resolution, `ctx.filter = blur`) so the shadows have a soft edge (`SHADOW_SOFT`). If the browser doesn't actually blur with `filter` (Safari/iPhone: `CAN_BLUR` is detected by testing a real blur), the shadows stay hard. An alternative blur that shrinks and re-enlarges the image was tried, but on iPhone the shadows flickered a lot, so it was removed.
4. The rat (`drawMouse`, procedural) and the lens glow are drawn after the darkness, so they're always visible. The rat is drawn opaque in its own canvas (`mouseCv`, only in a rectangle around it) and darkened with `source-atop` based on the light. Don't use `globalAlpha` to dim it: it becomes see-through and its overlapping parts show through.
5. The walls are taller than the rat, so they get drawn again on top of it, already lit (`wallCv × lightCv`, built in `litCv`), but only in a rectangle around the rat, and only their top faces (and door curtains seen from the front), masked with `topCv`; a side face facing the camera covers the rat only when the rat is on the other side of that wall (behind it), otherwise it stays under the rat, so when it presses against a wall its ears, head and paws show in front of the face instead of looking like they slip under the wall (the user noticed it on the walls above the rat).
6. Iris wipe: a black circle centered on the rat. Before it, `exitDarkness()` darkens the light and the rat while it crosses the exit threshold (exit row only). The cards (`card()`) are animated and never overlap: the one leaving shrinks fast (`.out`, `CARD_OUT_MS` 0.1 s) and the next one appears small and grows with a bounce (`.in`) only after it is gone (`CARD_GAP_MS`); if a card is still leaving, the new one waits; during a fade to black (`fading`) the old card vanishes at once and the new one enters as the screen clears. `pop(el)` does the same for HUD stickers (level and timer when a level starts).

**Rat animation**: everything is drawn in `drawMouse` in local coordinates (+x = forward, from x≈-20.5 at the rear to x=18 at the tip of the snout). Its anatomy follows a reference the user sent; a newer design, after another reference (`revision/ref-arriba.png`), is on while `MOUSE_V2` is true (false brings back the old one, which is kept): a teardrop body with a pointed head widening evenly to round hips, D-shaped ears (flat side against the head, rounded outside, one flat color, no inner ear), swept back by a shear (the harness front strap sits further back with this design, x = -1.8 instead of 1, at the user's request; `EAR_BACK` 0.35; 0 gives the first, straight version, which the user also liked; with the swept ears the front paws sit 1 unit further back, `FEET`, so their toes do not peek out; when an ear moves (twitch, bump, trap) it changes its slant and narrows a little instead of rotating, so its flat side stays on the head: rotated, the flat side showed as a diagonal cut over the head, which the user saw), bigger eyes set wider (x 11.2, ±4.1, radius 1.35), a wide, flat dome-shaped nose crowning the tip (no highlight: too small to see), which sniffs now and then while the rat stands still (`sniffAt`, like the front view), and three whiskers per side coming out of the cheek (forward, straight and back). In both, the body and head are a single `Path2D` silhouette (wide at the back, pointed at the snout), filled with one flat fur color, and the harness is clipped to it. The ears are ovals that grow backward from the sides of the head, with the pink inside shifted toward the body. They're tilted outward by `EAR_TILT`, with the pivot at their back base on the body side. They're drawn before the flashlight (under it), with their own head-rotation transform; the rest of the face goes after. The eyes sit close to the snout, red with a white highlight (Albina used to have a red glow around them, `eyeGlow` in `skinOf`, which the user removed); closed, they're a short sideways line curving toward the back. The whiskers start next to the nose and fan out to the sides. The paws sit slightly under the body, with fingers pointing forward and outward: the front ones are beside the eyes, in front of the ears, and the back ones are at the hips. The flashlight on its back follows a later flat design the user sent (seen from above, head toward the snout): a pale lens strip, a wide gray head with a lighter front part, a dark neck that curves into a narrower dark body, a power switch (a pill with a gray knob on the rat's right), a dark grip band and a dark tail cap, and a big battery window with a thick black frame. It is drawn in the reference image's own coordinates (390 × 930, vertical, head up) mapped onto the back (`X`/`Y` in `drawMouse`, lens at x = 8.6, about 21.6 units long), in the reference's fixed grays for every rat, later retouched by the user over a screenshot (head #2f2f2f with its #676767 top, neck #212121, body #333333 with no grip band and no top border, back cap #0d0d0d, switch #212121 with a #424242 knob, battery frame #212121, green bar with a #43e773 shine, harness #212127). The window keeps the old battery bar (the user asked for it): it shows `timeLeft / timeLimit`, drains toward the tail, takes the HUD battery's color for the blocks left (`LAMP_COLORS`), and in the last `WARN_T` s blinks alternating its color with white (it used to go out); the window and the bar are a bit wider than in the reference (both at the user's request); the lens turns dim when the flashlight goes out. When it bumps into a wall, `hx()` compresses everything in front of the shoulders (the head pulls back) and `updateTail` adds a quick tail wag. The head turns on the neck (`NECK`, `M.headA`): the silhouette bends gradually (helper `P`) and the face (nose, ears, eyes, whiskers) rotates as a whole. It leads into the turn, and when idle `animMouse` sometimes makes it look to one side, or to one side and then the other, before returning. The paws step for real (`updateFeet`, `M.feet`, world coordinates):
- **Stepping:** the gait is tied to distance, not time. A cycle (`M.gait`) advances by how far the paws' rest spots (`FEET`) move, whether walking or spinning in place, at one cycle every `STRIDE` units. Each diagonal pair runs half a cycle from the other, so they're always in sync: slow means slow steps and fast means fast steps.
- **Phases:** a paw spends `SWING` of the cycle in the air, going from a bit behind its rest spot to a bit ahead. The rest of the time it's planted, still on the floor. Front and back paws have the same reach; to keep the hands close to the arms, their rest spot was moved back instead (a shorter reach makes them drift back while planted).
- **Stopping:** if it stops with a paw in the air, that paw finishes its step on its own.
- **Slip:** a planted paw follows the body by `FOOT_SLIP` (a slight drag). That allows a long `STRIDE`, so the steps aren't too fast at full speed, without the paws drifting away from the body.
- **In the air:** it shrinks, gets lighter and turns outward. The step sound plays when it lands.
- **Limbs** (`limb`): fur ovals that follow each paw (stretching and rotating), cover the gap between paw and body, and are drawn under the body. Thighs go from the hip to each back paw; thinner arms go from the shoulder to each front paw.
- **Glue:** the steps are slower and "tugging", and after leaving the glue it leaves sticky footprints (`G.prints`, `PRINT_LIFE`, `drawPrints`; made darker at the user's request so they show).

The torso sways and bounces to the rhythm of the steps. When the rat spins in place (`M.spin`: turning fast without moving forward), the head turns more and the torso compacts: shorter and a little wider. When it pulls free of the glue (`M.stretchT`, `STRETCH_T`, `stretchAmount`), the torso stretches and thins for a moment, with a small rebound (inertia). The flashlight is rigid: it undoes the torso scale (`tsx`/`tsy`) around its center (`FCX`), so it follows the back without deforming. When it gets caught in a trap (`M.caught`), both ears shake and the tail goes straight and wags side to side fast for `CAUGHT_T` (1 s, fading via `caughtAmp`), then it stays completely still with its eyes closed. From the moment it's caught it takes a squashed pose (`M.squash`): paws splayed (front ones forward and out, back ones stretched backward and out), torso flatter and wider, ears drooping to each side; `animMouse` makes no more gestures, the whiskers stop, and `updateTail`/`updateFeet` freeze; it also plays a rat squeal (`Snd.squeal`). The flashlight dips slightly every 5–11 s (`DIM_T`, `DIM_DEPTH`), smooth, not a flicker; after bumping several times in a row it falters (`G.faltT`, `FALTER_T`): a couple of quick dips that fade on their own. Footsteps vary in volume, pitch and duration each time, and they're muffled (lowpass-filtered noise plus a soft low thump, no highs). On a wall bump there's a 70% chance of a squeal (`Snd.squeak`) that varies in pitch, length, number of chirps and direction.

The tail is also in world coordinates: it's a chain of `TAIL_N` points (`M.tail`, computed in `updateTail`). Each point moves toward a rest shape (a ripple tied to `M.phase`, a sway tied to `G.time`, and a curl tied to `M.turnV`), keeps the segment length fixed and is pushed out of the wall rectangles, so it never goes through walls. It's looser toward the tip, so it lags behind during turns (inertia). Safeguards so it never goes through a wall, which happened on iPhone: the body has a third collision circle at the hip; the tail root moves toward the rat if there's a wall on the body axis; each point moves at most `MAX_STEP` per frame (less than the cardboard thickness); and when rebuilt (`resetRun` sets it to `null`) it starts bunched at the base and grows backward (before, it was built straight and went through the start pen wall). `animMouse()` drives the gestures: the bump against a wall (`M.bumpT`: ears flap, whiskers tremble, eyes close), the random blink (`blinkT`), and the left or right ear twitch (`twitch`), which only happens after a second without input.

**States** (`G.state`): `title` → (`select`) → `intro` → `play` ⇄ `paused` → `won` | `dying` → `lost` (`G.dieReason`: `time` or `trap`). The cards are HTML (`#card`), and the HUD is DOM over the canvas, the same on PC and mobile (after a layout the user sent; its stickers, `.tape`, use the new cards' format: straight paper chips with rounded corners and a button-like bottom shadow, without border (like the floating buttons; the user prefers floating things borderless), the level as a dark tag sitting on the top edge of the clock, and coins, cheese and battery 8 px apart; the loose buttons of the Bioterio and the Máquina, `#screen .sbtns .cbtn`, are styled like the cards' buttons too, with "Activar" in yellow): the coin counter at the top left with the cheese counter under it, the level label small and centered above the timer, and the gear at the top right. There is no house button in the HUD anymore (it is inside the pause panel). The canvas is `position: fixed; inset: 0` and its size comes from `clientWidth`/`clientHeight`. Don't go back to `100vh`: on phones it includes the browser bar and pushes the camera off center. After following the rat, the camera keeps it inside `safeZone()`: 15%–85% of the screen, and on mobile between 80 px below the HUD and 66% of the height (so it doesn't end up under the HUD or under the thumb using the joystick). When time runs out, the light flickers and goes out (`dying`) and you go back to the start of the same maze. The camera (`camTarget`) follows the rat with some lookahead and is clamped to the maze edges when the maze is larger than the screen.

**Input**: directional control on both platforms, with no tank controls (the user tried them and changed their mind, and the gyroscope was dropped too because it was uncomfortable). Each frame, `update()` computes a target direction on screen. It comes from the floating joystick on mobile (`Stick`, with `#stickZone` covering the screen and the base `#stick` appearing where you put your finger) or from the arrows/WASD on PC (↑ = up, and they combine into diagonals). The rat turns toward that direction gradually, limited by `TURN`, and moves at `SPEED × magnitude × cos(angle difference)`, so it first turns and then moves forward. Space, click or tap trigger `primaryAction()`. Mute is saved in `localStorage` (`raton.muted`).

**Sound** (`Snd`): the effects are all synthesized with WebAudio (oscillators and filtered noise, no files), including the "whoosh" of cards entering (`cardIn`) and leaving (`cardOut`). `Snd.init()` runs on the first keypress because of the browsers' autoplay policy. On iPhone the ring/silent switch mutes Web Audio (all the effects) while the music, an `Audio` element, still plays (the user heard no effects with the phone in silent mode), so `Snd.init` sets `navigator.audioSession.type = 'playback'` when it exists (Safari 17+) and resumes the context whenever it is not `running` (iOS can leave it `interrupted`). Effects added later: `tap` for every card and options button (`act`, except Jugar, which has its own click; the Música / Sonido switches), `gateLand`, a soft thud when a nearby gate reaches the bottom (detected by its cycle phase), and a squeak when you tap a rat in the Bioterio (after `WAG_DELAY`). The music is the only file: `audio/laberinto-de-circuitos.mp3`, in `Music` (an `Audio` element on loop, separate from WebAudio). It starts on the first tap or keypress (already on the title screen; browsers don't allow audio before a gesture), fades in to a low volume (`Music.vol`, so it doesn't drown out the effects), and pauses and resumes with the pause. Music and effects have separate switches in the gear panel and separate mute states (`raton.musicMuted` / `raton.muted` in `localStorage`; keys M / F). In the browser pane the mp3 doesn't load, because the local file opens as a `data:` snapshot. Test it at the Pages URL.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

HTML game prototype: a lab rat escapes a dark cardboard maze with a flashlight strapped to its back. All the code lives in `index.html` (inline CSS and JS, no dependencies, no build step); the only assets are the music in `audio/` and the logo in `img/logo.png` (840 px web version; the original is in `concept/logo.png`). The game is called **Maze Mouse**. The only external resources are the Google Fonts fonts (Permanent Marker, Special Elite), with fallbacks. `concept/` holds the reference concept art (top-down view, cardboard walls with a corrugated edge, white rat with a harness) and the game doesn't load it.

The UI, the code comments and the README are in Spanish (Rioplatense, with voseo: "presioná", "escapaste"). Keep that tone.

## Run and test

There are no commands for building, linting or running tests. You open `index.html` in a browser, and with the built-in browser pane that's `preview_start` with `url: file:///C:/Claude/Laberinto/index.html`.

Quirks of the browser pane that affect testing:
- The page loads as a `data:` snapshot, so after each edit you have to navigate to the URL again.
- `requestAnimationFrame` is heavily throttled there, so simulated keypresses barely move the rat. To test logic, call the global functions directly from `javascript_tool`. Top-level `const` and `function` declarations are reachable from there. For example, `keys['arrowup']=true; for(...) update(1/60); render();`.
- `loadLevel(n)`, `startPlay()`, `resetRun()` and `castRays(x,y)` let you set up any situation. Setting `G.light=1` and calling `render()` gives you a lit frame for a screenshot.
- In the pane the `data:` URL has no `localStorage` (the game tolerates it with try/catch); to test progress, look at `Story.data`.
- Mobile mode can't really be tested in the pane, because with the local file touch emulation doesn't trigger on reload. Add the `touch` class to the `body` and simulate the finger with `PointerEvent` (`pointerdown`/`pointermove`/`pointerup`, using the same `pointerId`) on `#stickZone`. Final testing is on a real phone, at the Pages URL.
- The canvas can be 0×0 when the page loads, so `resize()` keeps it at least 1 px. In `frame()`, `requestAnimationFrame` is scheduled before `update`/`render` so that an exception doesn't kill the loop.

## Script architecture (`index.html`)

**Tunable constants** at the top: `C` (cell size, 64 world units), `T` (wall thickness), `K` (apparent wall height), speeds, `LIGHT_R`/`CONE` (flashlight), `RAYS`. Progression comes from `SIZES`/`sizeFor(n)` (maze columns×rows), `viewCells(n)` (how many cells across fit on screen, i.e. the zoom, which gets closer with each level) and `timeFor(n, pathCells)` (time limit from the shortest path length).

**Modes** (`G.mode`):
- **Challenge** (`loadLevel(n)`): infinite random levels. The seed is `G.baseSeed + n*7919`, and the base seed changes with every new game.
- **Story** (`loadStory(i)`): fixed levels from the `LEVELS` table (`seed`, `size`, `loops`, `traps`/`sticky`/`cheese`/`doors`, `intro`, optional `time`). It uses the zoom and time factor of challenge level 5 (`STORY_VIEW`) plus extra time for cheese and glue.
- **40 levels:** each mechanic is introduced on its own and then combined. Levels 1–6 are cheese, 7–12 glue (with some cheese), 13–20 traps (with glue and cheese), 21–28 doors (with everything before), and 29–40 everything together. Mazes grow from 10×6 to 24×14, with more items as they go. Time is computed automatically; the level selector scrolls (5 per row, 4 on mobile). All levels were checked to place every item they ask for.
- **Progress:** (`UNLOCK_ALL` is true for now, for testing: every level shows unlocked; set it to false to go back to unlocking one by one.) `Story` saves it in `localStorage` (`raton.story = {unlocked, stars[], best[]}`; `best` is the best time per level). Stars (`starsFor(time)`): ★ for escaping, ★★ for taking less than `G.star2` and ★★★ for less than `G.star3` and, in cheese levels, all the cheese. Both times are computed per level by `starTimes(extra)` (called from `loadStory` and `loadLevel`, so Challenge has them too) from the ideal route (shortest path at full speed, `pathLen · C / SPEED`) times 1.8 and 1.3, plus the same cheese and glue extra as the time limit and a fixed +3 / +2 s (turns cost time, especially in small mazes), rounded; the level intro card shows them (with the "Tiempo límite"). The HUD clock counts UP in both modes (time used, `fmtUp`), the same unit as the results and goals; the limit shows in the flashlight battery and the siren (a small label under the clock with the next star was tried and removed). Each star earned for the first time in a level gives `STAR_COINS` (5) coins.
- **Results screen** (both modes; in Challenge, whose mazes are random, the previous time, record and new-star coins count while you repeat that same maze, `G.chBest`/`G.chStars`, the level label says "Desafío W × H", and the back arrow goes to the title), in the order the user asked for and in the game's cardboard style: "¡Escapaste!", level, stars that drop in one by one (`.rstars`), the previous best ("Tiempo anterior", only if there was one) and then your time, as two taped cards in marker font (`fmtS`, whole seconds with no decimals, written "seg." because a lone "s" looked like a 5 in the marker font; times are floored and records compared in whole seconds too), with a red "¡Nuevo récord!" stamp right above your time when you beat it (the row only gets the extra top margin then), the cheese chip in cheese levels (coins are not shown here, the top counter has them), "Próximo objetivo" as a yellow taped note (`nextGoal`, from THIS run's stars: the next star's requirement, or beating your record with three), the machine notice and two buttons, "Repetir" (`retry`) and "Siguiente"; "Niveles" is a back arrow at the top left of the screen (`#btnBack`, on the results, on the level select, and on the Ratitas and Máquina screens, which have no "Volver" button anymore (on the machine only while it is at rest or showing the prize); from the select and Challenge it goes to the title, from Ratitas it closes the screen; the coin counter moves under it, `#coins.below`). Plenty of space between the parts.
- **Shared building:** both modes go through `buildMaze(W, H, seed, loopFrac)`.

**Menus**: `title` (logo, controls and the Story/Challenge/Ratitas/Máquina buttons, with no intro text or mode descriptions; keys 1/2) → `select` (level grid for Story titled "NIVELES", with no description, no scrollbar, no bottom button and no SPACE hint: the top-left arrow goes back and SPACE still plays the last unlocked level) → `intro` … The card buttons use `data-act` and are resolved in `act()`. The global click handler checks them before `primaryAction()`, and in `title`/`select` a click outside a button does nothing. Pause and options live in one panel (`#opts`, `openOpts`/`renderOpts`/`closeOpts`), opened by the gear button at the top right (`#btnGear`, the only button there) or P/Esc: while playing it pauses and shows "PAUSA", Música and Sonido switches, the house (back to the title, also Q) and "Reanudar"; on any other screen the gear opens the same panel as "OPCIONES" with "Cerrar", on top of whatever card is showing. Toggling Música/Sonido only slides the switch (`renderOpts` updates the open panel in place instead of rebuilding it). A provisional test button, "Luz", sits at the bottom right of the title and select screens (`#btnLight`, `debugLight`, saved in `raton.debugLight`). When on, the game adds an even ambient light (`DEBUG_AMBIENT`) to `lightCv`, so the whole maze is visible; the flashlight and everything else work as usual. On mobile and touch screens the scrollbars are hidden, though you can still scroll. The title and select screens use `titleBackground()`: a fixed maze sized to the screen (4 cells larger, rebuilt if the size changes, `G.titleSize`) with the camera fixed at its center, so its edges never show on PC or mobile, and no rat (`render` skips it when `menu`), softly visible thanks to an even ambient light (`MENU_AMBIENT`, only in menus; the game keeps total darkness). Every 2–5.5 s an old bulb flickers somewhere on screen for a moment (`menuFlicker`, `MenuFl`), a round light (`drawBulb` instead of the flashlight cone) cut by the walls.

**Maze** (`genMaze`): recursive backtracker on a W×H grid. Walls are stored as `hW[r][c]` (top wall of row r) and `vW[c][r]` (left wall of column c). The entrance is always on the right side (`entRow`) and the exit on the left (`exitRow`). `loopFrac` opens walls to create cycles. `bfs(m, c, r)` returns maze distances, used by `pathLen` and to place items. "Retry the same level" relies on not regenerating: `resetRun()` only repositions the rat, resets the timer and restores the items.

**Items** (`G.items`, generated in `placeItems` from the level rng, so they're fixed):
- **`trap`**: only in dead-end cells off the shortest path and away from the entrance and exit, facing the opening. Touching it closes it and calls `startDie('trap')`, which shows "¡ATRAPADO!". It's a procedural placeholder until the user sends an image.
- **`sticky`**: a tray that slows you down, and the more paws on it the stronger the brake (`STICKY_ON` minus `STICKY_PAW` per paw; with all 4 at 14%). After leaving it you recover from `STICKY_SLOW` over `STICKY_T` s (`stickyFactor`). It only goes on straight corridor stretches (two cells in a row with walls on both sides, never at junctions or corners), centered and almost as wide as the corridor. More likely near the exit.
- **`cheese`**: preferably off the path. A level can place more than it asks for (`cheeseGoal`), so there are a few to spare. `G.cheeseTotal` is the goal, the HUD (`#cheese`) shows collected/goal, and reaching it counts toward the stars.
- **`door`**: a one-way door in a wall between neighboring cells that are 8 or more cells apart through the maze, at least 3 cells from other doors and never in a cell another item uses (they replaced the cardboard-roll tunnels). Side A has the hole and side B has a thin cardboard curtain, larger than the hole, hung by tape above it. A is the cell farther from the exit, so it's a shortcut toward the exit. `doorSolids` cuts the wall at the hole in `G.solids` and adds the hole as its own rect (`d.rect`, with `door`); `G.rects` stays whole, so walls are drawn and block light as before (with a curtain lifted, `castRays` uses `G.holeRects`, which have the hole). `doorCheck` (at the start of `collide`): if the rat touches the hole with its center on side A, `d.passing` and the hole stops colliding until the rat leaves it. From side B it's a wall and the curtain rattles (`d.rattle`). Approaching from A slightly off-center, a funnel nudges the rat toward the middle. The tail ignores the holes. `updateDoors`: the curtain angle (`d.ang`, spring) rises with how far the rat sticks out on side B, falls when it leaves, hits the frame (`Snd.flapShut`) and rests at `DOOR_REST` so its edge shows from above.
- **Look:** the drawings follow photos the user sent, seen from above:
  - Trap (`drawTrap`): wooden board, wire bail, spring, metal trigger plate and a cheese cube.
  - Glue (`drawSticky`): black plastic tray with bluish-gray glue, corner screws and a center button. It's rectangular (`TRAY_L`×`TRAY_W`) and laid along the corridor; it counts as stepped on if it touches the rat's body.
  - Cheese (`drawCheese`): a wedge with a curved rind and 3D effect. Its top face is projected like the wall tops, with height `CHEESE_H`, and you see the sides facing the camera. Its size is `CHEESE_SCALE`.
- **Gallery:** `index.html?galeria` shows all the items large and lit, plus the rat for scale, to review designs with the user. In the browser pane the query string is lost, so call `window.render = renderGallery` instead.
- **Drawing:** traps, glue and cheese are drawn in `drawFloor`, so they're only visible with light. Doors (`drawDoors`) are drawn in `drawWalls` in three passes, projected with the wall parallax: the curtain behind the wall when the camera is on side A ('back'), the dark hole on the side face of A ('hole'), and the curtain plus hinge tapes in front when the camera is on side B ('front'). Since they're in `wallCv`, a lifted curtain covers the rat as it passes underneath. A dark shadow on the floor on side A (`drawDoorShadow`) marks the hole from above, along with a strip of caution tape like the start one but darker (`drawStartTape` with `shade`).

**Coins and rats** (phase 2, based on Crossy Road; placeholder art):
- **Coins** (`coin` items, `placeCoins`): placed so they create decisions, not chores (the user's design): on the shortest path only a few single coins (about one every `COIN_PATH_GAP` cells), and off the path treasures of 2 to 8 coins, worth about one coin per `COIN_DETOUR_S` seconds of detour (detour = extra cells to pass through that cell, from two BFS, entrance and exit), preferring dead ends; in a row along a straight corridor (two rows if more than 4) or in a ring. The direct route is fastest but pays little; exploring pays more but costs time (and the ★★★ time only leaves room for small treasures). `G.coinsTotal` counts them for the results screen. They use their own rng (`seed + 777`) so they don't move the other items. Picked up by passing near them (generous radius, like cheese; `Snd.coin`). They're kept even if you lose (`Wallet`, `raton.coins` in `localStorage`), and collected coins stay collected when retrying the same level. `drawCoin`: silver coin after a design the user sent (one light gray face, `COIN_FACE`, with two full-width grooves, each a dark line, a mid-gray body and a light line below: `COIN_BANDS`, no outline) that spins on itself like a flat cylinder (slower as it passes edge-on, without stopping, and faster showing a face: the angle is warped with a double sine), and at the same time it slowly rotates around its center (`COIN_ROLL`), so the flip axis keeps turning: the face narrows with the cosine of the turn and the edge band (`COIN_T` thick) widens with the sine, so edge-on only the side rectangle shows, with the grooves continuing across it; the back face is a darker version of the front (`coinBack`) with three thinner, evenly spaced grooves instead of two (`COIN_BANDS_BACK`, after another reference of the user; the edge continues the grooves of the face that shows), so you can tell which side is showing as it turns; picking one up throws small white diamond sparks (`G.fx` with `sq`, spinning and shrinking); `COIN_ICON` builds the same design as an inline SVG for the HUD and buttons, with a gray outline as wide as the HUD cheese icon's. The item gallery (`?galeria`) shows it spinning and facing front. The counter `#coins` is always visible at the top left corner, a bit bigger (under the back arrow on the screens that have one); the cheese counter goes under it in the game, and the win card shows `+N` (`G.runCoins`).
- **Rats** (`RATS`, 20 entries: name, fur, ears, harness, flashlight body, eyes, paws/tail, plus spots for Pandita): `skinOf(i)` builds the full palette (shades mixed with black/white) and `drawMouse` takes every color from `curSkin()`. Sitting, the tail moves like a cat's in a seamless loop: a wave travels from the base to the tip (each piece of the chain turns from its rest shape, more toward the tip and with a delay, plus a second harmonic for the tip flick; `TAIL_W` speed, `TAIL_SWISH` amount), while the part lying on the floor stays still. Breathing stretches only the belly: the head, ears and face are not deformed, they just rise and fall with it (`lift`). Every so often the head tilts a little to one side or the other, or back to the middle, at random but deterministic from `t` (`headTilt`: segments of `HEAD_SEG` s, each with its own target, start time and duration, eased; pivot at the neck, `HEAD_PIVOT`), and after the machine landing it waits until the bounce is over. A neck fill on each side (a curve from the widest point of the head, wherever the tilt puts it, down to the side of the belly) removes the pinch between head and body, so the outline stays smooth when the head tilts; curled up it shrinks into the ball. Every so often one hand gives a quick shake that dies out, pivoting at the wrist where the arm ends (`handShake`, segments of `HAND_SEG` s per hand, `HAND_SHAKE_T` long), never during the landing. `land` (seconds since it touched the floor) plays a landing bounce, a chain of damped rebounds each a bit later than the previous one: the body squashes and widens with the pivot at its base (the back feet stay put), the hands follow slightly later, then the head drops, rises a bit past its place and settles, then the nose, then the whiskers (tips more than the base); the ears open outward, the tail bounces and the eyes close for an instant on impact. The animation runs in its own `requestAnimationFrame` loop on `#gachaCv` (`Gacha`, `gachaUpdate`, `drawGacha`), in named stages (`GACHA_STAGES`, durations in `GACHA_T`). `gachaStage(id)` starts each one with its sounds and effects and calls the hook `Gacha.onStage(id)`, so the game can control it or hook into it. The rhythm follows what the user described with onomatopoeias:
  - `wake`: the top lights turn on one by one. The beacon and the light under the cap fade in smoothly (the user asked for it), the tubes switch on with a click and, while running, blink alternately (one on while the other is off, `TUBE_HZ` times per second, soft edges); while running, the cap light flickers without jumps and the beacon works like a real rotating siren (after a GIF the user sent): a mirror turns inside the red dome around the bulb, (`beaconSpeed`, `BEACON_T`: one turn every 1.05 s at constant speed, on a different rhythm from the tubes; the user tried easing profiles and preferred none); facing the camera it gives a short but wide white-pink flash with a big halo (drawn full screen on `#gachaFx`, since inside the machine canvas it got cut at the edge and showed a box), sideways the glare slides to one side and narrows, and from behind the dark back of the mirror shows softly in the middle. The glare and the dark back crossfade with no jumps; the white flash happens when the mirror faces the camera, and at that moment it lights the machine from the front (a pink-white tint over `machOff` with `source-atop`). When the motor stops the beacon doesn't cut off: it slows down and fades out (`Gacha.spinA`; everything inside the dome fades with it), and the beacon light itself dims slowly during `clack` and `door`. Lights start from their idle level (never reset to 0, which looked like a blackout), and the screen bars only go up (1 lit at rest, then 2, 3, 4 with the motor). After a prize the machine was out of view, so "Otra vez" brings it back at rest and fades it in (`Gacha.reappear`).
  - `run`: "ru rur ru ru ru rururu rururururu ruru ru ru ru" (`motorEnv`, `machinePhysics`). The motor starts slow, speeds up and slows down again, with a `Snd.ru` on every pulse. First only the base vibrates, a little and then more and more, with small upward hops. Halfway through the dome joins (glass, cap, red beacon and tubes, `mach.cpl`) with its own tremor and wobble, and then the tubes rotate from where they attach to the cap (`mach.tub`). It is deterministic, with no springs, and deforms nothing. The capsules jiggle when the dome moves, more at the motor's peak, but they travel little (small kicks, firm springs): what grows is a fast tremor in place (`c.jx`, `c.jy`, `c.ja`, fast sines with a phase per capsule, scaled by the motor), drawn on top of their position. When the motor stops they keep doing small rebounds from inertia: their energy (`Gacha.capE`) follows the motor up but decays slowly, and it softens their springs, damping and gravity, with no new kicks; and the beacon's round halo is drawn on a full-screen canvas behind everything (`#gachaFx`, `drawGachaFx`). The red beams that used to sweep the whole screen were removed at the user's request (`#gachaFx2`, the layer in front of the machine, stays empty).
  - `clack`: a capsule falls inside (you hear it, you don't see it). The pile in the dome drops one level (`capsDrop`): the lowest capsules (as many as the top row) sink behind the base and are removed, and the rest are reassigned row by row to the lower slots, so they slide down softly on their springs without crossing. They don't all start at once: the ones next to the hole go first and the rest follow, later the farther they are (`c.wait`, `c.th`).
  - `door`: "pssssst" (`Snd.hiss`). The arched door lights up and the gray door slowly rises (`DOOR_LIFT`, leaving a strip of door at the top); as soon as it starts rising, the ramp inside (golden brown `#9d7f41` with a lighter `#d2ac5d` top edge, colors the user picked) lowers (`TRAY_UP` → `TRAY_DOWN`) more slowly than the door, so the door finishes first (`DOOR_OPEN_T`) and the ramp later (`RAMP_FROM` → `RAMP_TO`, braking very slowly at the end), with the prize capsule resting on top of it, which ends at `MACHINE_DOOR`.
  - `launch`: silence. The capsule jumps toward the camera with an arc and a mid-air bounce, while the machine quickly fades out in place (`MACHINE_FADE`; the user didn't want to see it move back, so `MACHINE_RECEDE` is 1); it is drawn on `machOff` so it fades as a whole, and the camera never moves.
  - `hover`: the capsule stays in front for a moment.
  - `reveal`: the two halves shoot apart with a flash and confetti. At that same instant the rat jumps from keyframe 1 (`KF1`: the front-facing rat curled into a ball at the center of the capsule) to keyframe 2 (`KF2`: the same rat sitting; `KF2.size` is its height). It travels in an arc with a full counterclockwise spin while `curl` goes from 1 to 0, so its pieces unfold into place (no crossfade), and lands with the landing bounce; it is never seen sitting still as a ball. (`drawRatBall`, the old side-view ball, is no longer used there.) Behind it, full-screen speed lines like a reference the user sent (`drawSpeedLines` on `#gachaFx`: wide rays of varied widths from the capsule point, lime green and white, fading toward the screen edges so the text stays readable; to stay light on phones they are drawn once per prize into a small offscreen canvas, `speedCv`, at most `SPEED_MAX` px, and each frame only pastes it rotated; once the rat has landed they fade out smoothly and leave the screen black, `SPEED_HOLD` / `SPEED_FADE`) and star sparkles; when it lands its name pops in right under it, drawn on the canvas with a dark outline (`NAME_Y`), with "¡Ratita nueva!" or the duplicate refund under it; the only button is "Otra vez", in the same spot as "Activar" (no "Usarla"; you pick rats in the Bioterio), and there are no texts while the machine runs, so the layout never shifts (`#gachaBtns` keeps its height when empty). The rat drawings are never deformed.

**Siren**: with 10 s or less left (`G.siren`, 0..1), `drawSiren` tints `lightCv` red with `multiply` and adds a rotating red wedge centered on the maze. Walls don't block it (it comes from the ceiling), and it's transparent at the center so you never see the source. The siren sound (`Snd.wail`, an "Uuuuh" that rises for `WAIL_UP` s and then fades slowly over almost 2 s, its pitch dropping as if it were moving away) plays once per turn of the beam (one turn every 2 s, angle `G.time·π`): it starts `WAIL_UP` s before the beam passes over the rat (`G.wailUntil`), so the peak lines up with the light sweeping over it.

**Geometry** (`buildRects`): walls are turned into rectangles (collinear runs merged, plus a start pen outside the entrance). That single list `G.rects` is used for collision (circle vs rectangle, two circles: body and head), for ray casting, and for drawing. `buildDeco` adds purely visual elements: sheet seams, floor tape and pencil marks, which work as landmarks. On the floor, at the mouth of the start pen, there's a yellow and black caution tape (`drawStartTape`) so the start is obvious without reading.

**Rendering pipeline** (`render`). This is the core of the visual look and needs care when you touch it:
1. Fully lit scene: floor (`drawFloor`, using a tiled texture pattern) on the main canvas, and walls (`drawWalls`) on `wallCv`. For the 3D effect, each wall's top face is the base rectangle scaled by `(1+K)` around the camera, and only the side faces facing the camera are drawn.
2. Light map: `castRays` fires `RAYS` rays from the flashlight against the wall edges (all axis-aligned) and gets a visibility polygon. On `aCv` the beam sprite (`coneCv`, generated pixel by pixel at startup) is drawn, clipped with `destination-in` to that polygon. That's the floor light. On `bCv` the same beam is clipped to a polygon extended by `T+6` (plus its version projected by `(1+K)`) and to the shape of `wallCv`, so the top faces and sides of the walls get lit. Both are added (`lighter`) into `lightCv` over black.
3. `multiply` of `lightCv` over the scene: anything without light stays fully black. "Total darkness" is a design decision: lit areas are not remembered. Before it's added to `lightCv`, the floor light goes through `blurCv` (half resolution, `ctx.filter = blur`) so the shadows have a soft edge (`SHADOW_SOFT`). If the browser doesn't actually blur with `filter` (Safari/iPhone: `CAN_BLUR` is detected by testing a real blur), the shadows stay hard. An alternative blur that shrinks and re-enlarges the image was tried, but on iPhone the shadows flickered a lot, so it was removed.
4. The rat (`drawMouse`, procedural) and the lens glow are drawn after the darkness, so they're always visible. The rat is drawn opaque in its own canvas (`mouseCv`, only in a rectangle around it) and darkened with `source-atop` based on the light. Don't use `globalAlpha` to dim it: it becomes see-through and its overlapping parts show through.
5. The walls are taller than the rat, so they get drawn again on top of it, already lit (`wallCv × lightCv`, built in `litCv`), but only in a rectangle around the rat.
6. Iris wipe: a black circle centered on the rat. Before it, `exitDarkness()` darkens the light and the rat while it crosses the exit threshold (exit row only). It closes when you go through the exit, and the win card appears once it's closed (`showWinCard`). It opens in `startPlay`. Its state is `G.iris` (1 = open) / `G.irisTarget`, and it takes `IRIS_T` seconds.

The wall light (`bCv`) is also blurred (`WALL_SOFT`) before being clipped to the shape of the walls, so the edge of the lit area on the wall tops doesn't look like a hard circle. Camera shake (`G.shake`) builds up when you bump several times in a row (less than 1.2 s apart). It only offsets the camera while drawing (`render` adds it to `cam` and takes it back off at the end).

The cards have no "Presioná ESPACIO" hints, only buttons ("Encender la linterna" → `start`, "Seguir" → `resume`, "Reintentar" → `retry`); SPACE still does the same as the main button. The cards (`card()`) are animated: the one leaving shrinks (`.out`, 0.13 s) and the next one appears small and grows with a bounce (`.in`). `pop(el)` does the same for HUD stickers (level and timer when a level starts).

**Rat animation**: everything is drawn in `drawMouse` in local coordinates (+x = forward, from x≈-20.5 at the rear to x=18 at the tip of the snout). Its anatomy follows a reference the user sent. The body and head are a single pear-shaped `Path2D` silhouette (wide at the back, pointed at the snout), and the harness is clipped to it. The ears are ovals that grow backward from the sides of the head, with the pink inside shifted toward the body. They're tilted outward by `EAR_TILT`, with the pivot at their back base on the body side. They're drawn before the flashlight (under it), with their own head-rotation transform; the rest of the face goes after. The eyes sit close to the snout, red with a white highlight (only Albina has a red glow around them, `eyeGlow` in `skinOf`); closed, they're a short sideways line curving toward the back. The whiskers start next to the nose and fan out to the sides. The paws sit slightly under the body, with fingers pointing forward and outward: the front ones are beside the eyes, in front of the ears, and the back ones are at the hips. The flashlight on its back (inspired by a hand flashlight the user sent: bluish-gray body, yellowish COB panel) has a battery bar that shows `timeLeft / timeLimit`. It drains toward the tail, turns orange below 25% and red below 10%, and blinks in the last 10 s. The head and lens of the flashlight (x 4..8.6) shouldn't be changed: the user likes them as they are. When it bumps into a wall, `hx()` compresses everything in front of the shoulders (the head pulls back) and `updateTail` adds a quick tail wag. The head turns on the neck (`NECK`, `M.headA`): the silhouette bends gradually (helper `P`) and the face (nose, ears, eyes, whiskers) rotates as a whole. It leads into the turn, and when idle `animMouse` sometimes makes it look to one side, or to one side and then the other, before returning. The paws step for real (`updateFeet`, `M.feet`, world coordinates):
- **Stepping:** the gait is tied to distance, not time. A cycle (`M.gait`) advances by how far the paws' rest spots (`FEET`) move, whether walking or spinning in place, at one cycle every `STRIDE` units. Each diagonal pair runs half a cycle from the other, so they're always in sync: slow means slow steps and fast means fast steps.
- **Phases:** a paw spends `SWING` of the cycle in the air, going from a bit behind its rest spot to a bit ahead. The rest of the time it's planted, still on the floor. Front and back paws have the same reach; to keep the hands close to the arms, their rest spot was moved back instead (a shorter reach makes them drift back while planted).
- **Stopping:** if it stops with a paw in the air, that paw finishes its step on its own.
- **Slip:** a planted paw follows the body by `FOOT_SLIP` (a slight drag). That allows a long `STRIDE`, so the steps aren't too fast at full speed, without the paws drifting away from the body.
- **In the air:** it shrinks, gets lighter and turns outward. The step sound plays when it lands.
- **Limbs** (`limb`): fur ovals that follow each paw (stretching and rotating), cover the gap between paw and body, and are drawn under the body. Thighs go from the hip to each back paw; thinner arms go from the shoulder to each front paw.
- **Glue:** the steps are slower and "tugging", and after leaving the glue it leaves sticky footprints (`G.prints`, `PRINT_LIFE`).

The torso sways and bounces to the rhythm of the steps. When the rat spins in place (`M.spin`: turning fast without moving forward), the head turns more and the torso compacts: shorter and a little wider. When it pulls free of the glue (`M.stretchT`, `STRETCH_T`, `stretchAmount`), the torso stretches and thins for a moment, with a small rebound (inertia). The flashlight is rigid: it undoes the torso scale (`tsx`/`tsy`) around its center (`FCX`), so it follows the back without deforming. When it gets caught in a trap (`M.caught`), both ears shake and the tail goes straight and wags side to side fast for `CAUGHT_T` (1 s, fading via `caughtAmp`), then it stays completely still with its eyes closed. From the moment it's caught it takes a squashed pose (`M.squash`): paws splayed (front ones forward and out, back ones stretched backward and out), torso flatter and wider, ears drooping to each side; `animMouse` makes no more gestures, the whiskers stop, and `updateTail`/`updateFeet` freeze; it also plays a rat squeal (`Snd.squeal`). The flashlight dips slightly every 5–11 s (`DIM_T`, `DIM_DEPTH`), smooth, not a flicker; after bumping several times in a row it falters (`G.faltT`, `FALTER_T`): a couple of quick dips that fade on their own. Footsteps vary in volume, pitch and duration each time, and they're muffled (lowpass-filtered noise plus a soft low thump, no highs). On a wall bump there's a 70% chance of a squeal (`Snd.squeak`) that varies in pitch, length, number of chirps and direction.

The tail is also in world coordinates: it's a chain of `TAIL_N` points (`M.tail`, computed in `updateTail`). Each point moves toward a rest shape (a ripple tied to `M.phase`, a sway tied to `G.time`, and a curl tied to `M.turnV`), keeps the segment length fixed and is pushed out of the wall rectangles, so it never goes through walls. It's looser toward the tip, so it lags behind during turns (inertia). Safeguards so it never goes through a wall, which happened on iPhone: the body has a third collision circle at the hip; the tail root moves toward the rat if there's a wall on the body axis; each point moves at most `MAX_STEP` per frame (less than the cardboard thickness); and when rebuilt (`resetRun` sets it to `null`) it starts bunched at the base and grows backward (before, it was built straight and went through the start pen wall). `animMouse()` drives the gestures: the bump against a wall (`M.bumpT`: ears flap, whiskers tremble, eyes close), the random blink (`blinkT`), and the left or right ear twitch (`twitch`), which only happens after a second without input.

**States** (`G.state`): `title` → (`select`) → `intro` → `play` ⇄ `paused` → `won` | `dying` → `lost` (`G.dieReason`: `time` or `trap`). The cards are HTML (`#card`), and the HUD is DOM over the canvas, the same on PC and mobile (after a layout the user sent): the coin counter at the top left with the cheese counter under it, the level label small and centered above the timer, and the gear at the top right. There is no house button in the HUD anymore (it is inside the pause panel). The canvas is `position: fixed; inset: 0` and its size comes from `clientWidth`/`clientHeight`. Don't go back to `100vh`: on phones it includes the browser bar and pushes the camera off center. After following the rat, the camera keeps it inside `safeZone()`: 15%–85% of the screen, and on mobile between 80 px below the HUD and 66% of the height (so it doesn't end up under the HUD or under the thumb using the joystick). When time runs out, the light flickers and goes out (`dying`) and you go back to the start of the same maze. The camera (`camTarget`) follows the rat with some lookahead and is clamped to the maze edges when the maze is larger than the screen.

**Input**: directional control on both platforms, with no tank controls (the user tried them and changed their mind, and the gyroscope was dropped too because it was uncomfortable). Each frame, `update()` computes a target direction on screen. It comes from the floating joystick on mobile (`Stick`, with `#stickZone` covering the screen and the base `#stick` appearing where you put your finger) or from the arrows/WASD on PC (↑ = up, and they combine into diagonals). The rat turns toward that direction gradually, limited by `TURN`, and moves at `SPEED × magnitude × cos(angle difference)`, so it first turns and then moves forward. Space, click or tap trigger `primaryAction()`. Mute is saved in `localStorage` (`raton.muted`).

**Sound** (`Snd`): the effects are all synthesized with WebAudio (oscillators and filtered noise, no files), including the "whoosh" of cards entering (`cardIn`) and leaving (`cardOut`). `Snd.init()` runs on the first keypress because of the browsers' autoplay policy. The music is the only file: `audio/laberinto-de-circuitos.mp3`, in `Music` (an `Audio` element on loop, separate from WebAudio). It starts on the first tap or keypress (already on the title screen; browsers don't allow audio before a gesture), fades in to a low volume (`Music.vol`, so it doesn't drown out the effects), and pauses and resumes with the pause. Music and effects have separate switches in the gear panel and separate mute states (`raton.musicMuted` / `raton.muted` in `localStorage`; keys M / F). In the browser pane the mp3 doesn't load, because the local file opens as a `data:` snapshot. Test it at the Pages URL.
